## 3. 名字与草稿

- 使用 `Intl.Segmenter` 按用户感知字符计数；中文、组合 emoji 与组合字符均按完整字符处理。去除首尾空白后计数，内部空格仍计数。
- 草稿保留实际输入；最终确认名字使用去首尾空白后的值。不用截断输入来强行限制 12 字。
- 空值提示“先给小猫起个名字吧。”；超长提示“名字最多 12 个字哦。”。
- 组合输入期间禁止继续，结束后再更新校验。代码已有 IME 处理，但原生中文输入法尚未实测。
- A↔B、C 返回与 A 改选猫均保留名字草稿；改选后只更新角色图。
- 独立 `sessionStorage` 键为 `cat-letters-ui-adoption-flow-v1:page-stage-01`，支持当前标签刷新恢复。没有账号同步或跨设备能力；关闭标签、清理浏览器存储后的持久性不作保证。

## 4. 状态与恢复边界

| 状态 | 允许操作与恢复 |
| --- | --- |
| UNCONFIRMED | 选择、起名、返回修改；有效猫和名字才可提交 |
| SUBMITTING | 保留猫和名字，阻止重复提交与返回修改；刷新恢复为 UNKNOWN |
| UNKNOWN | 只“重新读取”既有模拟结果，不能重新创建、换猫或改名；无效／缺失结果保持 UNKNOWN |
| ERROR | 明确失败，保留输入；“再试一次”可提交，也可返回修改 |
| CONFIRMED | 展示已确认猫与名字，仅提供“继续和它生活”；无普通换猫、改名或二次创建入口 |

读取到有效确认结果时以该结果为准；读取明确失败才转 ERROR。UNKNOWN 不因为空结果而擅自重提。`REVIEW_CHOICE` 仅在 C 且未确认／明确失败时回 A，普通 `BACK` 仍为 C→B→A。

正常流程提交／读取约 900ms，为本机模拟。`?scene=` 独立状态样例不读写完整流程草稿；其中提交中、读取中样例保持静态状态便于审阅。图片重试沿用原 catId 和原文件，不替换成另一只猫。“继续和它生活”只显示本批流程出口，不制作第二批首页。
