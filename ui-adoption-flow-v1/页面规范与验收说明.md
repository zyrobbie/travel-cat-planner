# UI-01A–C · 页面规范与验收说明

**V1.0 · 待用户验收 · 2026-09-26**

## 1. 范围与沿用基线

本轮仅完成初遇选猫、起名、领养确认三组页面及关键状态原型。依据本轮页面需求，复用指定已批准提交 `6bcf546c797ee2f633a9c3e6865f303901966f0b` 的组件视觉。来源与字节校验记录见 [asset-manifest.json](asset-manifest.json)。

沿用按钮、选择卡、输入边界、提示、字体、配色、圆角与焦点语言；`flow.css` 只适配页面宽度、2×2选择布局、单行名字输入、48px主按钮及字号放大。选择卡移除上阶段的介绍文案，仅保留完整猫图、外观名和选择状态。页面不显示角色基准板，不新增角色、场景、性格标签或推荐机制。

4张全身像均为1122×1402 RGBA，使用 `contain` 等比展示。A页的1:1是图片展示区域，不将角色原图裁成正方形。B/C预览通常为200×200px，小屏为160×160px；短视口与键盘布局使用112×112px预览以留出输入空间。

## 2. 三页规则

| 页面 | 主任务与内容 | 交互规则 |
| --- | --- | --- |
| A 初遇与选猫 | 标题“选一只你喜欢的小猫吧”；四猫2×2；短说明；继续 | 首次未选择，继续禁用。点卡片仅选择，保留当前页；选中由边框、勾选和文字共同表达。点击继续才到B |
| B 起名 | 已选猫；字段“小猫的名字”；计数与错误；继续 | 输入草稿在返回、改猫、再次进入时保留。有效名字才能进入C；超长内容保留以供修改，不截掉正在输入的文字 |
| C 领养确认 | 已选猫、猫名、固定领养规则；再看看 / 确认领养 | 未确认时可返回修改；提交中锁定操作；明确失败可重试；UNKNOWN仅可重读；确认后无改选或改名入口 |

固定提示直接显示，不折叠：

> 每个账号只能领养一只小猫。确认后，将无法更换或领养其他小猫。请确认你的选择。

本机边界说明：

> 当前为本机测试体验；这里演示正式版的领养规则。

“继续和它生活”只显示本轮完成与后续衔接说明，不进入尚未设计的首页。

### 名字与中文输入

- 使用 `Intl.Segmenter('zh', { granularity: 'grapheme' })` 按用户可见字符计数；复合emoji、国旗和组合字符不按UTF-16长度拆算。
- 计数前去掉两端空白，中间空格仍计入；有效范围1–12。草稿保留原输入，确认名字去掉两端空白。
- 空值文案：`先给小猫起个名字吧。`；超长文案：`名字最多 12 个字哦。`
- 中文组合输入期间不提交、不中断选词；`compositionend` 后更新校验、计数和按钮状态。代码包含该处理，浏览器与实际输入法检查记录见进度表。

## 3. 状态、刷新与模拟结果

状态模型为 `selectedCatId`、`catNameDraft`、`step`、`adoptionStatus` 和可选 `confirmedCat`。纯状态模块不读写浏览器；会话恢复由 `flow.mjs` 单独处理。

| 状态 | 可执行动作 | 数据规则 |
| --- | --- | --- |
| UNCONFIRMED | 选猫、起名、往返、有效值确认 | 改猫不清空名字；选择不等于领养 |
| SUBMITTING | 等待结果 | 保留猫与名字；拒绝再次提交和返回修改 |
| ERROR | 重试，或返回修改 | 只用于明确失败；原选择与名字保留 |
| UNKNOWN | 重新读取 | 不允许再次创建或回去换猫；有效确认记录转CONFIRMED，明确失败转ERROR；缺失或无效结果仍保持UNKNOWN |
| CONFIRMED | 继续和它生活 | 使用已确认结果，不提供换猫或改名路径 |

正常流程使用独立 `sessionStorage` 键：`cat-letters-ui-adoption-flow-v1:tab-demo`。保存本原型状态和模拟已存结果，支持同标签页刷新恢复；不读写正式应用键，也不使用真实账号或后台。

刷新时若此前是SUBMITTING，恢复为UNKNOWN，仅允许重读。读取到有效模拟结果后显示已确认的猫与名字；若读取明确返回ERROR且没有有效确认记录，则转为ERROR并允许重试。有效确认记录始终优先，空结果或无效记录不能解锁重试。上述成功与明确失败两条刷新恢复路径均已实测。

会话内容损坏或无法读取时，代码设计为展示恢复读取提示、保留原记录，不自动用新领养替代；该故障分支仅静态审查，尚未做浏览器故障注入。

正常流程的提交与重读使用约900ms定时模拟，不产生网络请求。默认返回成功；`?outcome=ERROR` / `?outcome=UNKNOWN` 用于测试本次载入首次提交的不同结果。页面展示“确认”或“已确认”只代表本机演示状态，不构成真实领养和账号承诺。

### 状态稿与正常流程隔离

审阅页通过 `?scene=<状态ID>` 打开独立样例，使用固定示例猫与名字。所有scene实例都不读取或写入正常流程的会话键。

- `C-submitting`、`C-reading` 是停留式静态状态，便于截图；不会自行在900ms后跳转。
- 其他可操作样例可演示本地切换；重载样例会回到该fixture的初始状态。
- `B-keyboard` 的键盘为带明确标注的布局占位，不是系统键盘截图或真机验证。

## 6. 验收方式与边界

先在[审阅页](review.html)逐状态看布局，再通过[完整流程](index.html)操作A→B→C。需核对选择不跳页、草稿往返和刷新恢复、失败重试、未知只读、确认锁定，以及独立scene不污染草稿。

可访问性目标沿用需求：普通文字对比至少4.5:1；有意义图标和边界至少3:1；独立操作区至少44×44px，主按钮至少48px高；键盘焦点明确。选择卡整体是交互目标，内部勾选图形无需单独承担点击。实际测量结果与设备覆盖必须写进进度记录，不仅凭源码声明达标。

本预览已在线发布供用户与团队审阅，状态仍为待用户验收。发布前19组纯状态测试已通过；本地IAB视口与完整流程检查已完成，线上验证范围以部署记录为准。真实中文输入法、真机软键盘及未经实测的浏览器仍需单独验收。静态稿与模拟保存不代表真实领养后台已接入。

只有用户明确通过A/B/C、关键状态和指定响应式后，才可标记“UI-01A–C 初遇与领养流程｜V1.0 验收通过”。本轮不自动进入首页、需求回应、发送成功或旅行首页。
