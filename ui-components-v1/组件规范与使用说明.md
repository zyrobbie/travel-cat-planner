### 1.3 演示边界

- 样稿可点选猫咪、展开故事、输入文字，并切换本地反馈样式。
- 点选不完成真实领养；“寄出”“回信已收好”等内容只用于展示状态，不发送信件、不写入后台，也不宣称已保存。
- 语音入口保留。点击入口展示不可用提示并保留当前文字；另一张静态状态卡演示正在说话的视觉效果，不调用麦克风，不录音、不计时、不转写。
- 当前页面内的输入仅用于演示。刷新、关闭或切换演示栏目可能重置内容，不能用来保管真实回信。
- 本轮止于组件提案与交付，不自动进入六个完整页面、高保真页面开发、Figma 组件库或线上接入。

## 2. 统一视觉规则

图片承担情绪，卡片组织信息，文字建立陪伴感。让插画与故事成为注意力中心；用暖纸面、适量留白和轻边线承接内容，不使用聊天气泡、任务面板、等级数值或强悬浮效果。

### 2.1 色彩提案

| 语义 / 样稿变量 | 色值 | 使用方式 |
| --- | --- | --- |
| 页面底色 `--bg` | `#F5F1E8` | 暖米色背景 |
| 纸面 `--paper` | `#FFFCF6` | 便签、明信片、输入区、记录卡 |
| 正文 `--ink` | `#493D34` | 主文字、重要信息 |
| 次级文字 `--muted` | `#76695C` | 日期、轻提示、简短说明 |
| 主强调 `--accent` | `#A6532F` | 主按钮、选择反馈、焦点与操作入口 |
| 强调悬停 `--accent-hover` | `#884124` | 主按钮 hover / pressed |
| 浅橘 `--soft` | `#FBEEE2` | 轻提示与柔和交互背景 |
| 装饰边线 `--line` | `#E3D9CB` | 纸面边缘、内容分隔 |
| 控件边线 `--control-line` | `#94816F` | 输入框、次按钮、未选 radio 的可辨识边界 |
| 成长 `--green` | `#526B43` | 成长日期与温和完成反馈 |
| 旅行 `--blue` | `#446B7B` | 地点标签与旅行信息 |
| 夜色 `--night` | `#465772` | 夜间或特殊情绪的辅助语义；不替整张卡大面积染色 |

浅色分隔线只作装饰，不替代输入控件的功能边界。重要状态同时用文字、勾选或焦点轮廓表达，不只依赖颜色。插画本身不加滤镜或覆盖色来匹配色板。

### 2.2 字体与层级

| 内容 | 基准字号 / 行高 | 字体与规则 |
| --- | --- | --- |
| 来信、明信片、记录标题 | 22 / 32px | `Kaiti SC` → `STKaiti` → `KaiTi` → `Songti SC` → `serif`；短标题保留轻手写感 |
| 正文、可编辑输入 | 16 / 28px | `PingFang SC` → `Microsoft YaHei` → `system-ui` → `sans-serif`；较长阅读块可放宽至约 30px 行高 |
| 时间、地点、辅助提示 | 13 / 20px | 系统中文无衬线；保留足够对比度 |
| 主要操作按钮 | 15 / 22px | 中等字重，点击高度至少 44px |

上述为基础层级；状态板的说明文字不属于产品正文。明信片、记录卡的短摘要采用约 15 / 28px 的紧凑阅读变体，输入正文保持 16px。标题与长文自然换行，不靠缩小字号塞入固定高度。

字体使用本地后备链，样稿不依赖外部字体下载。PNG 记录当前制作环境的字体效果；其他系统打开 HTML 可能使用后备字体，需在正式接入时核对换行。手写感用于短标题，长正文不通篇使用装饰字体。

### 2.3 圆角、边距与阴影

| 项目 | 本轮提案 |
| --- | --- |
| 间距阶梯 | 4 / 8 / 12 / 16 / 24 / 32 / 48px |
| 日常便签圆角 | 16px |
| 明信片圆角 | 8px |
| 猫咪选择卡圆角 | 20px |
| 输入控件圆角 | 12px；外层回信纸面为 16px |
| 成长记录圆角 | 12px |
| 主、次按钮圆角 | 10px |
| 常规纸面内边距 | 24px；明信片保留较窄的纸边；窄列选择卡可使用 10–16px |
| 轻阴影 | `0 3px 12px rgba(73, 61, 52, 0.045)` |
| 键盘焦点 | 2px 强调色轮廓，常规外偏 4px；输入框外偏 2px |

圆角作用在 UI 容器上，不用容器裁掉猫耳、尾巴、胡须或脚。状态变化以色彩、轮廓、文案为主，避免连续漂浮、放大跳动和复杂粒子效果。

## 3. 素材与响应式使用

### 3.1 素材角色与完整性

本轮目录引用 13 张原 PNG：4 头像、4 全身像和5张场景示例。完整场景库仍为既有20图；未出现在本轮样稿中的场景不需要另做新图。

| 素材 | 已核对尺寸 | 放置方式 | 主要组件 |
| --- | --- | --- | --- |
| 头像 `V1-cat-avatar-cat-01…04.png` | 1280×1280 RGBA，1:1 | `object-fit: contain`，保留透明边缘；便签头像示例为48×48px | 日常需求卡、身份提示 |
| 全身像 `V1-cat-fullbody-cat-01…04.png` | 1122×1402 RGBA | 等高图位、等比完整显示；不裁成正方形，不拉宽狸花来匹配橘白 | 猫咪选择、确认呈现 |
| 场景 PNG | 1536×1024，3:2 | 宽度随容器，3:2原比例，`height: auto` / `contain` | 明信片、成长记录 |

头像用于身份与来信状态；全身像用于选猫与确认呈现；场景用于旅行和回忆。示例中的奶油白为当前 cat-03，不使用历史黑白猫版本。角色名、头像、全身像和场景中的猫必须来自同一角色编号，不能用另一只猫作加载占位。

本轮保持原文件、原构图和原颜色。若正式产品需要压缩或派生规格，应另行确认并验证；本轮不声称已经交付 WebP、动画、额外裁图或新场景。

### 3.2 布局基准

| 手机视口 | 左右留白 | 标准单列卡宽 |
| --- | --- | --- |
| 360px | 各16px | 328px |
| 390px（主基准） | 各16px | 358px |
| 430px | 各16px | 398px |

标准桌面阅读位的单列组件最大420px。审阅板可并排展示多个状态；总览中的成长记录另展示图文并排的宽版用法，图片仍完整显示。

猫咪选择集合保留至少两列的展示方向：手机两列，390px 时12px列间距对应单卡约173px；桌面空间足够时可四列。四只猫在本轮设计板全部展示，实际页面可自然纵向滚动，不要求四卡挤在一屏内。单卡状态示例可独立放大，不能据此把真实选择集合改成大图单列。

内容变长时卡片增高：标题可多行、正文自然换行、按钮保持可触达，图片比例不变。窄屏按钮允许换行；不通过压扁插画或隐藏关键操作解决空间不足。

## 4. 五类核心组件

### 4.1 日常需求卡 / Daily Note

**用途：** 小猫提出一个小问题、困惑或请求，像一张写给用户的便签。

**信息顺序：** 头像与姓名 → 时间 → 来信标题 → 正文 → 回复入口。姓名与标题分层，不把整张卡做成对话气泡。

| 状态 / 变体 | 本轮呈现与操作 |
| --- | --- |
| 默认 | 橘白“小橘”的窗边光点来信，正文留出自然段落，底部“给它回信” |
| 交互 | 按钮 hover / pressed / 键盘焦点；点击“给它回信”切至回复输入栏目并聚焦输入区 |
| 内容变化 | 奶油白“小白”的雨天来信，变更头像、称呼、时间、标题与正文，结构不变 |

**使用规则：** 头像48px、标题22px，纸面内边距24px。一次只强调一个回复动作，不叠加任务进度、热度、点赞、奖励或倒计时。来信字数变化时卡片向下扩展。

**接入状态约定：** 加载时保留基本布局；加载失败在原位说明并提供重试。没有来信时不能伪造一封“真实来信”来填满卡片。本轮未连接来信服务，样稿里的信件始终是示例。

### 4.2 旅行明信片卡 / Travel Postcard

**用途：** 展示小猫寄回的风景与故事，形成可以收藏回看的明信片感。

**信息顺序：** 完整场景 → 地点 → 标题 → 小猫故事 → 日期与全文入口。用轻纸边、文字和留白建立明信片感；邮票、邮戳不是必填项，不为装饰挤占插画。

| 状态 / 变体 | 本轮呈现与操作 |
| --- | --- |
| 默认 | 莱茵河谷场景及故事摘要，原图3:2完整显示 |
| 交互 | 点击“读读这张明信片”原位展开后续故事，再次点击“收起全文”恢复摘要状态 |
| 内容变化 | 萤火虫、灯塔场景，地点、标题、正文与日期同步变化 |

**使用规则：** 外层12px纸边、8px圆角；图片不裁成长横幅，不叠大标题遮挡猫或风景。地点采用旅行蓝，小于故事标题，不做旅游宣传海报。展开只增加文字区域，不改变原图比例。

**接入状态约定：** 图片未到达时保留3:2占位，失败时显示可读提示；不换成别只猫或别个地点的图。展开按钮保留可见焦点并同步展开状态。样稿不提供收藏、转发或真实邮寄功能。

### 4.3 猫咪选择卡 / Cat Choice

**用途：** 初遇选择与确认领养时的角色呈现，让用户先看见小猫。

**信息顺序：** 完整全身像 → 猫咪名称 → 一句简短介绍 → 选择状态。外观和介绍服务于连接感，不提供能力数值、稀有度或性格评分。

| 状态 / 变体 | 本轮呈现与操作 |
| --- | --- |
| 默认 | 未选中的狸花卡，提供“想认识它”提示 |
| 交互 | 整张卡可点选；选中态用强调色轮廓、勾选和“已选择”文字共同表达 |
| 内容变化 | 橘白、狸花、奶油白、三花共用结构，保留各自真实身形与比例 |

**使用规则：** 同一组采用原生 radio 单选。鼠标或触控点卡片选择，键盘可进入并用方向键移动；选中后仍可在本组改选。此行为只演示选择，不代表后台已完成领养。

全身像采用相同图位、`contain`等比适配；猫的视觉宽窄差异属于角色身份，不以拉伸纠正。确认场景复用同一角色图与选择摘要，完整命名、确认与保存流程留给后续页面设计。

**接入状态约定：** 角色图片加载失败仍显示本猫名称与重试说明，不替换角色。不可用状态要有文字理由及禁用语义；不能只降低透明度或移除外轮廓。本轮不引入不可选猫种、付费解锁或稀有度机制。

### 4.4 回复输入组件 / Reply Composer

**用途：** 让用户感觉在给小猫留一句话。保留文字输入、语音入口、提交操作和轻提示。

**信息顺序：** 收信称呼 → 有标签的输入区 → 轻提示 / 错误反馈 → 语音入口与主按钮。placeholder辅助起笔，不能代替字段标签。

| 状态 / 变体 | 本轮呈现与操作 |
| --- | --- |
| 默认 / empty | 空白文本，提示“一句话也可以”；空白或只有空格时禁用寄出 |
| 输入 / filled | 非空内容启用主按钮；输入框有明确焦点轮廓 |
| 内容变化 | “写给小橘” / “写给小白”示例，布局一致 |
| 提交中 / loading | 静态“正在寄出…”示例，提交按钮禁用，内容只读，避免重复操作 |
| 失败 / error | 静态未寄出示例；说明失败并保留原文，提供重试入口 |
| 成功 / success | 点击本地提交后切换反馈样式；回看入口用于回到刚才的文本，不代表真实保存 |
| 语音入口不可用 | 点击“用语音说”显示不可用说明；已经输入的文字保留，可继续编辑 |
| 正在说话 | 独立静态录音态示意，提供改用文字与结束操作的视觉位置；不产生真实音频或转写 |

**尺寸与版式：** 外纸面内边距24px，输入区最小高168px，内边距约14×16px，12px圆角，16px输入字号。主按钮与语音入口都至少44px高，窄屏允许换行。长文本向下扩展，不用强制字数截断替代布局适配。

**交互边界：** 本轮提交直接演示本地成功样式；loading、error与正在说话卡用于查看视觉状态，不模拟网络结果或录音过程。语音控件没有隐含授权，不请求麦克风权限。

**正式接入必须保持：** 提交失败保留原文及收信对象；处理中避免重复提交；结果不明不能显示“已保存”，应先确认结果。语音不可用或权限未获准时保留文字路径，不能清空用户已写内容。真实录音、转写与持久化不在本轮交付范围内。

### 4.5 成长记录卡 / Growth Journal

**用途：** 回顾小猫经历、用户互动与细小变化，像共同日记中的一页。

**信息顺序：** 时间 → 故事标题 → 完整图片 / 插画 → 简述 → 展开入口。成长绿只作日期与小标记的辅助色，不给故事配等级或数值。

| 状态 / 变体 | 本轮呈现与操作 |
| --- | --- |
| 默认 | 窗边重见光点的日常记录，时间、标题、图与摘要清楚排列 |
| 交互 | “翻开这一页”原位展开当时回应与后续；“合上这一页”收起 |
| 内容变化 | 三花出发的旅行记录，结构一致，标题和摘要允许自然换行 |

**使用规则：** 12px纸面圆角、24px内边距，照片保留3:2构图。桌面宽位可将图文并排；移动按既定顺序上下阅读。用户回应与小猫故事通过轻分隔区分，不做成绩单或成就墙。

**接入状态约定：** 无记录时使用简短邀请式说明，不制造虚假的连续天数。内容或图片加载失败保留时间、标题与重试路径；展开/收起不改变记录内容。此处故事均为样例，不是从用户账户读取的历史。

## 5. 跨组件状态与接入约定

本节约定后续实现应保留的状态行为，不代表本轮已经接通对应服务。HTML中可点击的行为以各组件表格和演示边界为准。

| 状态 | 统一要求 |
| --- | --- |
| 默认 | 信息主次清楚；每个组件有一个主要阅读或操作方向 |
| hover / pressed | 轻微改变底色或边线；不依靠放大卡片提示可点 |
| 键盘 focus | 焦点可见、顺序符合阅读顺序；按钮可用键盘触发，选择组使用radio语义 |
| selected / expanded | 颜色之外有文字或图形提示；可操作控件同步语义状态 |
| disabled | 原生禁用语义，阻止触发；有需要时说明原因，不让用户猜测 |
| loading | 保留内容占位与用户输入，避免版面跳动和重复提交 |
| error | 提示出现在相关内容附近；说明可继续的动作，不用全局空白页取代原文 |
| success | 仅在操作结果确认后表达成功；设计演示始终有演示说明 |

图片提供用途明确的替代文本；装饰图标不重复朗读按钮文案。输入字段保留标签，动态反馈采用温和状态提示，不自动抢走输入焦点。布局优先用自然文流，让较长中文和系统文字放大后仍能读完。

## 6. 本轮验收与后续交接

验收时先看390px主基准，再对照360px、430px与桌面状态板。需要确认：

1. 五类组件均有默认、交互 / 选择、内容变化和使用说明，语音入口没有遗漏。
2. 角色与场景完整显示；小猫身份对应正确，未被裁切、拉伸或重新绘制。
3. 选中、焦点、禁用和展开状态清楚；文字输入与反馈的主次关系稳定。
4. 示范操作不让人误以为完成真实领养、录音、发送或保存；输入失败与语音不可用的示例保留原文。
5. 长标题、长正文与四猫集合可自然增长，手机不横向溢出，操作目标保持可触达。
6. 视觉接近温暖便签、明信片与共同日记，保持轻柔留白，而非聊天工具、任务系统或旅游广告。

本说明记录设计规则与交付边界，不把静态状态板等同于真实页面验收。正式接入仍需在目标设备中核对字体后备、键盘与触控、输入恢复、实际网络结果和素材加载。

用户验收后，再冻结本轮 token、组件状态和示例文案的采用范围；随后可据此开展初遇与选猫、首页、日常需求详情、回复、旅行明信片与成长记录等高保真页面设计。本轮不预先宣称这些页面已经完成。
