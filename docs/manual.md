## 📌 TL;DR

- 「有猫来信」V2 = **用户养育一只自由的小猫**：小猫像孩子一样向用户求助（需求卡），用户用自己的方式回应它；小猫带着用户的回应去生活、去旅行，把"你的话如何改变了我"以明信片寄回来——**用户在养育小猫的过程中，把自己重新养育了一遍**。

# 第一部分 · 项目概览（新人速读区）

## 0.1 这个项目是什么

「有猫来信」是一款**心理陪伴型（轻疗愈）产品**：

```text
领养小猫（它有自己的生活，自由游荡）
→ 回家留下「需求卡」——向用户寻求支持（建议/鼓励/应对困难，像小孩向妈妈求助）
  例：「今天是我第一次去隔壁小区，我有些担心那里的小猫会不会不喜欢我」
→ 用户回应（文字或语音；无标准答案；不会接时可看专业 tips）
→ 小猫带着用户的回应继续生活
→ 出远门 → 寄回明信片：分享见闻 + 联动此前的交互历程
  例：「想到你曾经鼓励我勇敢，于是我试了竹筏漂流」
→ 用户确认"我的话有力量" → 内化（循环继续）
```

**核心理念：疗愈在"给出"中发生**。用户对小猫说"累了就该休息""别怕，勇敢去试"——小猫真的照做并活出了这句话——用户意识到"原来我懂得如何温柔地对待一个生命"——这份温柔逐渐转向自己。**用户回应小猫的方式，往往就是他希望自己被对待的方式**：回应即投射，投射即自我认知，认知即改变的开始。

**V1 → V2 关系方向反转**（决策日志 D8）：V1 是"小猫陪伴用户、记住用户的话并回应"；V2 是"用户养育小猫"，明信片冲击点从"它记得我"变为"我对它产生了影响"。

# 第二部分 · 防信息损失区（理念根基 · 术语 · 红线）

> 本节存在的理由：未来大量工作由 AI 协作完成，对话会被压缩。**以下内容是本项目不可丢失的"根"**，任何后续产出（PRD、文案、交互、AI prompt 设计、内容库生产）若与本节冲突，以本节为准，除非决策日志中有明确变更记录。

## 1. 理念根基（三块基石 + 三层期望结果）

### 1.1 心理学根基（产品基调的终极裁决标准）

| 理念 | 内涵 | V2 中的应用 |
|------|------|------------|
| **Reparenting（重新养育自己）** | 成年后的情绪模式源于童年未被好好回应的需求 | **V2 的核心机制**。用户**亲自扮演养育者**，在养育小猫的过程中练习温柔回应需求——练习对象是小猫，内化对象是自己 |
| **温尼科特「足够好的母亲」** | 孩子不需要完美的照顾者，需要"足够好"、稳定可靠的照顾者 | 用户本人成为那个"足够好"的照顾者：**不需要完美回应，只需持续真实在场**。小猫绝不因用户的"不完美回应"而受伤或惩罚用户 |
| **叙事疗法「外化」** | 把内在情绪投射到外部载体上，比直面自己更安全 | 小猫是投射的安全载体：用户不敢对自己说的温柔，可以先对小猫说；不敢给自己的允许，可以先给小猫 |

### 1.2 期望结果（评估一切功能的标尺）

| 时间维度 | 期望结果 |
|---------|---------|
| 短期 | 每天 3 分钟，体验"被需要"和"我的话有力量"；在回应小猫中获得情绪松弛 |
| 中期 | 在持续的"需求—回应—影响"循环中，看见自己回应模式的变化轨迹；通过明信片册沉淀"我给予过的温柔" |
| 长期 | 把对待小猫的方式内化为对待自己的方式——累了允许休息、害怕时鼓励自己、不完美时也值得被温柔以待；建立更稳定的自我认同 |

## 2. 术语表（统一语言，防止歧义）

| 术语 | 定义 |
|------|------|
| **需求卡** | 发起方是小猫。内容是它的困境或愿望，简洁、小孩式，向用户寻求支持。例：「今天是我第一次去隔壁小区，我有些担心那里的小猫会不会不喜欢我」（V1"心愿卡"术语已废弃） |
| **回应** | 用户对需求卡的回答，文字或语音；**无标准答案**。用户怎么接，就是怎么对一个求助的生命说话。回应有双重价值：① 人格识别的输入；② 用户理想化存在方式的投射 |
| **专业 tips** | 用户"不知道怎么回应"时环境中可见的心理学专业建议（倾听/共情/正常化等回应方式），轻声提示而非教学；由专业内容撰写 + 人工审核 |
| **识人期 / 留存期 / 成熟期** | 三阶段动态模型：识人期（**第 1–2 天**，相对密集的统一需求卡快速识别）；留存期（建议第 2–4 周，附近活动 + 高频需求卡 + 24–48h 明信片，防早期流失）；成熟期（第 5 周起，短途与长途交替，更多元深度体验） |
| **人格特质** | 借鉴 16 型人格框架。**不设独立 onboarding**：用户选择小猫并起名后直接收到求助卡，通过识人期 1–2 天密集需求卡的回应识别用户人格倾向/潜在需求；驱动小猫倾向、需求卡选题、事件匹配、文案语气 |
| **特质混合** | 通过交互分析自然得出：每位用户为 **1 或 2 个特质**（不超过 2 个，不强制 2 个）；需求卡与反馈库随特质组合合并，按特质占比按比例出现 |
| **事件库** | 预制内容库主体之一：**不分型、全用户通用**（分型的是事件出来后小猫的需求与反馈，即需求卡）。含事件结构、基础文案框架、配图；覆盖家与附近/城市探索/远方旅行/勇气与挑战四类场景；建议规模 100–150 个通用事件（V2.1 起不再按 16 型分别建事件） |
| **需求卡库** | 预制内容库主体之二：**按 I/E/N/S/T/F/J/P 八字母维度划分**（16 型每型由 4 个字母组成），再结合特质认定分配；**每型分配总数必须为 4 的倍数**（每字母维度等量贡献）。建议每字母维度 16 张母库（共 128 张），每型按 4 字母各取 8 张 = 32 张/型；含识人期统一卡 |
| **记忆联动（V2 定义，V2.1 细化）** | 明信片联动的是**用户给小猫的回应**（而非 V1 的"用户写给自己的话"）：小猫因为用户的话做出不同选择并分享尝试后的感受。**明信片回应方向必须与用户当时的回应一致**（用户说"做自己"，明信片就是"做自己"的成功体验）；需求卡事件（求助类）数量远多于明信片联动事件（回响类），实际执行随机对应、不要求一一对应。冲击点=**"我对它产生了影响"**。红线 R5 约束其真实性 |
| **AI 限权** | AI 只做三件事：识别用户回应 → 匹配人格特质 → 关联预制事件与文案框架；**不做面向用户的开放式自由生成**；模板填空也须安全过滤（红线 R8） |
| **惊艳感衰减** | （保留）核心体验（回应→影响力确认）初次很惊艳，随次数增加可能产生"套路感"导致情绪价值递减的风险；V2 中主要靠事件库梯度与特质混合对冲 |
| **Gate（验收门槛）** | 阶段出口必须满足的客观条件，由主理人主持、产品负责人签字，不过门不进入下一阶段 |
| **MVP** | 最小可行产品，V2.1 中专指"验证『回应→影响力』闭环所需的最小形态"：新闭环 + 简化版人格识别 + 最小内容库（规模与字母维度分批方式待收敛会拍板） |

## 3. 设计红线（任何阶段不得逾越）

| # | 红线 | 理由 |
|---|------|------|
| R1 | **绝不做"惩罚式"设计**：用户不回应、回应敷衍、长时间不上线，小猫不得表现出失望、生气、受伤或任何情感绑架 | 「足够好的母亲」理念——用户本人就是那个"足够好"的照顾者，不需要完美，只需真实在场；情感绑架对目标用户是伤害 |
| R2 | **不承诺治疗效果**：产品定位是"轻疗愈陪伴"，所有文案不得暗示可替代心理咨询/治疗 | 伦理底线 + 合规底线 |
| R3 | **危机信号必须有应对机制**：用户**在回应中暴露自己的危机信号**（自伤/抑郁/自杀暗示）时，产品不得用普通明信片机制"接住"，必须有专门的识别与转介路径（热线信息、求助资源引导） | V2 中回应里藏着用户自己，风险敞口比 V1 更大；情感伦理底线 |
| R4 | **AI 相关内容必须过安全审核管线**：任何触达用户的内容（预制文案、模板填空、tips），必须经过安全过滤后才可发出 | 防止内容翻车造成二次伤害 |
| R5 | **联动必须真实**：明信片引用的必须是用户**真实给过的回应**，不得伪造"你曾经说过…"（模板套用假装呼应） | 这是产品信任根基，一旦被识破即崩盘 |
| R6 | **先验证最危险假设**：在人格识别准确性与内容供给质量未验证前，不投入任何非核心功能开发 | 资源保护原则（V2 最危险假设=人格识别 + 内容库工程） |
| R7 | **善终机制**（方向已确认，细则待收敛会）：品类存在生命周期终点（参照旅蛙 2026-12-08 停运），任何模型更换/功能下线/服务终止必须有用户情感资产处置方案（数据导出/纪念册/温柔告别） | 用户投入的是真实情感与自我投射，产品有义务温柔地结束；罗比已在初始想法 V2 讨论中接受该方向 |
| R8 | **AI 限权**：AI 只做"识别用户回应 → 匹配人格特质 → 关联预制事件与文案框架"；不做面向用户的开放式自由生成；模板填空也须安全过滤 | 开放式生成存在质量失控、情感伤害、合规与法律风险（参照 AI 陪伴行业翻车与监管案例） |
| R9 | **心理识别透明**：人格识别结果与用途必须对用户透明（用户可查看、可理解"我的猫为什么是这样的"）；不得暗中做心理画像；数据最小化采集 | 心理数据属于敏感个人信息；暗中画像一旦暴露将摧毁信任并触发合规风险 |

## 16. 优先级框架（用于 Phase 8 及所有范围决策）

采用 RICE 评分：**Score = (Reach × Impact × Confidence) / Effort**

| 维度 | 含义 | 评分参考 |
|------|------|---------|
| Reach | 影响多少用户 | 每周期触达用户数 |
| Impact | 对用户影响多大 | 3=巨大 2=高 1=中 0.5=低 |
| Confidence | 评估确信度 | 100%/80%/50% |
| Effort | 工作量 | 人周 |

> 特别规则：凡涉及**「回应→影响力」核心体验**（需求卡质量、联动真实性、内容库深度）的项目，Impact 评分 × 1.5 加权（差异化钉子优先）；凡与红线 R1–R9 冲突的项目，无论得分一律否决。
