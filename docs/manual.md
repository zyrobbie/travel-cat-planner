## 📌 TL;DR

- 「旅行小猫」= 旅蛙式异步陪伴框架 + 核心差异化「记忆联动」：小猫记住用户写下的话，几天后以明信片把那句话"活成"一个画面寄回来。
- 全产品最危险假设是**记忆联动的可规模化实现**（AI 生成质量/成本/安全、惊艳感衰减），因此全线节奏贯彻一个原则：**先验证最危险假设，再写 PRD，再谈扩张**。
- 路线分 7 个阶段（Phase 0 已完成）：调研 → 概念收敛 → PRD/MVP → 设计开发 → 测试（含情感安全测试）→ 灰度上线 → 上线后迭代；每阶段有明确 gate criteria，不过门不进入下一阶段。
- MVP 范围**严格收敛**为验证「记忆联动」所需的最小闭环：心愿卡 → 用户书写 → 小猫出行 → 个性化明信片 → 回看，其余一切（商业化、社交、装扮等）一律 Later。
- 预计节奏（相对时间轴）：Now = Phase 1 三线并行调研（第 1–4 周）；Next = 概念收敛 + PRD/MVP（第 5–9 周）；Later = 开发测试上线（第 10 周起，视收敛会结论细化）。

# 第一部分 · 项目概览（新人速读区）

## 0.1 这个项目是什么

「旅行小猫」是一款**心理陪伴型（轻疗愈）产品**，形式参照《旅行的青蛙》的异步陪伴框架：

```text
领养小猫 → 小猫留下「心愿卡」（邀请用户自我表达的小任务）
→ 用户写下回答 → 小猫选择性领取后出门
→ 几天后寄回明信片/书信 → 明信片内容呼应用户之前写下的原话
→ 明信片沉淀为可回看的记录（循环）
```

**核心差异化 = 「记忆联动」**：明信片不是随机通用文案，而是延迟、具象化地呼应用户之前写下的原话。例：用户写过「自由的充盈感」，几天后明信片写「今天我仰起头看一棵很大的树，阳光从叶子缝隙里漏下来，那一刻我突然懂了，原来自由可以藏在任何地方」。

**产品想传递的**：心理咨询所传递的理念——**被看见，被认真对待**。让用户在低门槛的日常互动中，体验"养育与被养育"的亲密关系（本质是自己和自己的关系）。

> 本节存在的理由：未来大量工作由 AI 协作完成，对话会被压缩。**以下内容是本项目不可丢失的"根"**，任何后续产出（PRD、文案、交互、AI prompt 设计）若与本节冲突，以本节为准，除非决策日志中有明确变更记录。

## 1. 理念根基（三块基石 + 三层期望结果）

### 1.1 心理学根基（产品基调的终极裁决标准）

| 理念 | 内涵 | 对产品的决定 |
|------|------|-------------|
| **Reparenting（重新养育自己）** | 成年后的情绪模式源于童年未被好好回应的需求 | 「养育」具象化为"养一只会长大的猫"，用户在陪伴中练习温柔回应需求，这份温柔反射回自身 |
| **温尼科特「足够好的母亲」** | 孩子不需要完美的照顾者，需要"足够好"、稳定可靠的照顾者 | **猫咪绝不因用户"不完美回应"而惩罚用户**；重点是持续真实的在场，而非表现完美 |
| **叙事疗法「外化」** | 把内在情绪投射到外部载体上，比直面自己更安全 | 投射到猫身上再收到回应，让抽象情绪变得可被看见、可被处理 |

### 1.2 期望结果（评估一切功能的标尺）

| 时间维度 | 期望结果 |
|---------|---------|
| 短期 | 被认真对待、被记住的瞬间；情绪松弛与小惊喜 |
| 中期 | 可回看的明信片记录 → 「被自己陪伴」的稳定感 |
| 长期 | 内化「足够好」而非「完美」的自我关系模式，减少自我苛责 |

## 2. 术语表（统一语言，防止歧义）

| 术语 | 定义 |
|------|------|
| **心愿卡** | 小猫出门前留下的小任务，本质是邀请用户自我表达。例：「一个让你此刻心里一亮的词」 |
| **记忆联动** | 明信片内容延迟、具象化地呼应用户之前写下的原话（核心差异化，全产品最危险假设所在） |
| **选择性领取** | 用户完成心愿卡后，小猫不是每次必取（保留生命感） |
| **明信片** | 小猫出行数日后寄回的书信/图文内容，包含见闻 + 感受 + 对用户话语的呼应 |
| **惊艳感衰减** | 记忆联动初次体验很惊艳，但随着次数增加用户产生"套路感"导致情绪价值递减的风险 |
| **Gate（验收门槛）** | 阶段出口必须满足的客观条件，由主理人主持、产品负责人签字，不过门不进入下一阶段 |
| **MVP** | 最小可行产品，本项目中专指"验证记忆联动所需的最小闭环"，不是"功能不全的正式版" |

## 3. 设计红线（任何阶段不得逾越）

| # | 红线 | 理由 |
|---|------|------|
| R1 | **绝不做"惩罚式"设计**：用户不回复、回复敷衍、长时间不上线，小猫不得表现出失望、生气、受伤或任何情感绑架 | 「足够好的母亲」理念；情感绑架对目标用户（缺情感支持群体）是伤害 |
| R2 | **不承诺治疗效果**：产品定位是"轻疗愈陪伴"，所有文案不得暗示可替代心理咨询/治疗 | 伦理底线 + 合规底线 |
| R3 | **危机信号必须有应对机制**：用户倾诉自伤/抑郁/自杀信号时，产品不得用普通明信片机制"接住"，必须有专门的识别与转介路径（热线信息、求助资源引导） | 情感深度伦理边界，四大隐忧之三 |
| R4 | **AI 生成内容必须过安全审核管线**：任何寄给用户的明信片，无论 AI 生成还是模板，必须经过安全过滤后才可发出 | 防止 AI 翻车造成二次伤害 |
| R5 | **"被记住"必须是真实的**：记忆联动必须真的基于用户写过的内容生成，不得伪造"我记得你说过…"（随机文案假装呼应） | 这是产品信任根基，一旦被识破即崩盘 |
| R6 | **先验证最危险假设**：在记忆联动可行性未验证前，不投入开发任何非核心功能 | 资源保护原则 |

## 14. 变更管理（如何修改本手册）

1. **谁可以改**：任何成员可提修改建议；**只有路径（维护人）落笔修改**；涉及红线、范围、gate 的修改必须经方向明同意 + 罗比审定。

4. **防冲突**：本手册是单一事实来源；任何其他文档与本手册冲突时，以本手册最新版本为准。

## 15. 优先级框架（用于 Phase 7 及所有范围决策）

采用 RICE 评分：**Score = (Reach × Impact × Confidence) / Effort**

| 维度 | 含义 | 评分参考 |
|------|------|---------|
| Reach | 影响多少用户 | 每周期触达用户数 |
| Impact | 对用户影响多大 | 3=巨大 2=高 1=中 0.5=低 |
| Confidence | 评估确信度 | 100%/80%/50% |
| Effort | 工作量 | 人周 |

> 特别规则：凡涉及**记忆联动核心体验**的项目，Impact 评分 × 1.5 加权（差异化钉子优先）；凡与红线冲突的项目，无论得分一律否决。
