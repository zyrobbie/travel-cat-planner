## 统筹独立旧版升级与操作验证

统筹从旧应用提交单独导出并构建，重新得到相同脚本哈希；通过旧版本真实 UI 创建两只合成猫、六封信、两条回应、跳过与已读／未读状态，以及两段进行中的旅行。所有材料均为专门创建的合成内容，不读取或复制用户真实浏览器历史。

在独立持久浏览器中关闭旧程序，保持相同 `http://127.0.0.1:4174/travel-cat-planner/app/` 入口，切换到 E2-A 构建 `index-DN0vDZDL.js` 后实跑以下检查，均通过：

- 逐字段比较每个参与者、来信、正文快照、收到／阅读／跳过时间、旧回应、旅行、操作版本、历史事件和幂等记录，原有值不变。新增回应版本为 1，未知回应发送时间为 `null`，未臆造含义标签。
- 新版打开后刷新，数据完全一致，不重复迁移；两段原旅行 ID 均保留。
- 用迁移的实际旧回应人工核验并寄出河景 linked，归属于原进行中的旅行；首读没有来源入口，重开后可折叠查看真实原回应。
- 更正来源后，旧信显示当时使用的版本与已更正说明；已寄故事正文不变。
- 删除来源后，所有回应版本原文及内联副本清除，序列化普通记录不含被删原文；已寄故事正文仍保留，来源显示已删除。
- 上述删改不影响另一只猫的数据。另一只零回应猫仍可结束原旅行、再独立出发并收到完整 ordinary，原来信保留。
- 390px 无横向溢出，实际页面截图中的正文、署名、来源与收好按钮可读且无遮挡；页面运行错误为空。

证据位于 `/tmp/catletters-e2a-root-evidence/`：`before.json`、`after-migration.json`、`after-interactions.json` 和对应 PNG。可复现脚本为 `/tmp/catletters-e2a-baseline-check.mjs` 与 `/tmp/catletters-e2a-upgrade-check.mjs`。此轮为上述构建的独立验证，后续最终构建与发布结果另记，不将它冒称为线上或所有浏览器验收。

## 独立代码复核

已修复并复核：已有损坏数据库缺少 `participants` 时中止升级；ACTIVE 回应必须与需求卡当前指针一致；跨体验删除不会清空不相关草稿；初始读取保留明确的迁移失败原因和恢复提示。

旧记录升级在一个 versionchange 事务内完成，异常整体回滚。旧版连接收到版本变化后关闭，不能写入新版库。更正、删除与寄信使用同一对象存储的读写事务；删改先提交则旧联动失效，寄信先提交则保留快照并标记来源变化。新回应使用新 ID，不复活已删来源关联。

人工核验逐项呈现三篇故事要求，默认未确认，含义判断改变后清除勾选。回看按寄出时版本读取，已删原文不展示。该复核不等于自动识别用户含义或心理效果验证。
