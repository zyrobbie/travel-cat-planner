## 本轮规则

用户确认关闭应用只是离开互动，小猫的生活和旅行继续；需求卡与明信片共用一个未读新信位置。到期按时间顺序结算，保留第一封合法来信，其余被占位挡住的来信节点跳过、不积压。读完即可释放位置，无需回应；旅行结束不撤回已寄信。旧版多封未读全部保留，读完前不再新增。

GitHub Pages 使用当前浏览器 IndexedDB。关闭网页期间没有进程执行，重新打开、返回前台或页面可见时才实际结算；计划时间与实际写入时间分别记录。有限 14 日日历与演示快进共用规则，结束后不循环重寄。旧旅行保留 ID，升级后增加明确的剩余寄信和回家节点。

“留给自己的话”继续取消，不增加手动暂停开关。本轮没有真实 Push、云端账号、跨设备同步或 E5 自动语义匹配；人工来源核验、更正删除与已寄正文快照规则沿用 E2-A。详细范围见 [执行任务书](E2-B_程序员执行任务书.md)。

## 独立复核中处理的问题

- 旧旅行的 FIREFLY 选择因来源更正进入 `NEEDS_REVIEW` 时，迁移也须保留旅行场景；不能退回默认 RHINE。
- 回复和更正草稿持久保存，刷新后恢复，草稿不作为正式来源。返回已有新信时先显示新信入口，正在编辑时仅提示，不自动跳页、已读或发送。
- 打开信使用已读事务提交后的状态直接显示详情，不能依赖另一次成功读取；故障注入已改为实际 `get(id)` 路径。
- 迟到的人工核验／寄信先结算到期旅行；旧页面不能在旅行已结束后绕过规则。
- 迁移回滚测试在首条记录真实更新成功后，于第二条记录注入失败，再比较原数据库版本和全部记录，防止仅在首次写入前失败却声称覆盖全部回滚。
- 上方入口明确为“寄出普通旅行信”；已有待寄关联选择时不得由普通入口静默覆盖，状态层也执行相同限制。
