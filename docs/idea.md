## ⚠️ 版本变更说明

**V1 → V2（2026-09-08）**：关系方向反转。V1 是"小猫陪伴用户、记住用户的话并回应"；V2 是"**用户养育小猫**——在满足小猫需求、回应小猫求助的过程中，用户练习温柔地对待一个生命，并把这份温柔内化给自己（把自己重新养育一遍）"。两个已确认的关键认知：① **疗愈发生在"给出回应"的过程中，而非收到回应时**；② **明信片的情感冲击点是"我对它产生了影响"，而非"它记得我"**。

**V2 → V2.1（2026-09-09）**：产品定名「有猫来信」；人格识别方式、需求卡划分原则、特质混合规则、识人期时长、事件库分型方式、语音边界共 6 项机制修订（详见各节与版本记录）。

## 📌 一句话定位

一款心理陪伴型（轻疗愈）产品：用户领养一只自由的小猫。小猫会像孩子一样向用户求助（需求卡），用户用自己的方式回应它；小猫带着用户的回应去生活、去旅行，并把"你的话如何改变了我"以明信片寄回来——**用户在养育小猫的过程中，把自己重新养育了一遍。**

---

## 1. 核心理念：疗愈在"给出"中发生

心理咨询传递的核心体验是"被看见、被认真对待"。本产品的选择是：不让用户等待被看见，而是让用户**成为那个给出看见的人**。

```text
用户对小猫说"累了就该休息" / "做你自己就好"
   ↓
小猫真的照做了，并且活出了这句话
   ↓
用户意识到：原来我懂得如何温柔地对待一个生命
   ↓
这份温柔逐渐转向自己：那我是不是也可以这样对自己？
```

**用户回应小猫的方式，往往就是他希望自己被对待的方式**——回应即投射，投射即自我认知，认知即改变的开始。

---

## 2. 核心循环（三阶段动态模型）

### 阶段一 · 识人期（第 1–2 天）

- 用户选择小猫并起名字后，**上来就是小猫的求助卡**——不设独立 onboarding 环节，通过**相对密集的统一需求卡**（标准化的求助）在 1–2 天内快速完成识别
- 产品目标：**识别用户的内在特点与潜在心理需求**（他怎么回应困境、习惯鼓励还是安慰、对"休息/做自己/边界"的态度）
- 识别结果用于塑造小猫未来的性格倾向与交互方式

### 阶段二 · 留存期（建议：第 2–4 周）

- 小猫**更多在附近活动**（小区、街道、城市里被忽略的角落）
- **更高频的需求卡**（建议每日或隔日一张），更短周期的明信片（24–48h）
- 产品目标：快速建立"回应 → 看到影响"的闭环体验，形成关注习惯，防止早期流失

### 阶段三 · 成熟期（建议：第 5 周起，长期）

- **短途外出与长途旅行交替**：附近的新鲜角落 ↔ 远方的澳洲竹筏
- 明信片内容更多元、更有深度，联动更长跨度的交互历程
- 产品目标：给成熟用户持续的新鲜感与情感复利

```text
【日常循环】
小猫自由游荡（它有自己的生活）
   ↓
回家留下「需求卡」——向用户寻求支持
（建议 / 鼓励 / 应对困难的方式，像小孩向妈妈求助）
   ↓
用户回应（文字或语音；无标准答案；不会接时可看专业 tips）
   ↓
小猫带着用户的回应继续生活
   ↓
出远门 → 寄回明信片：分享见闻 + 联动此前用户给过的回应
（用户说过"做自己" → 小猫寄回一个"做自己"的成功体验）
   ↓
用户感受到：我的话是有力量的 → 它听见、记住、活出了我的话
→ 等于用户自己听见、记住、回应了自己（循环继续）
```

## 3. 关键机制

| 机制 | 描述 |
|------|------|
| **需求卡** | 发起方是小猫。内容是它的困境或愿望，简洁、小孩式。例：「今天是我第一次去隔壁小区，我有些担心那里的小猫会不会不喜欢我」 |
| **用户回应** | **无标准答案**。支持文字与**语音**回应（语音仅在后台转文字后做内容理解，不做情绪识别）。用户怎么接，就是怎么对一个求助的生命说话 |
| **专业 tips 兜底** | 当用户"不知道怎么回应"时，环境中可看到 tips——来自心理学/心理咨询专业内容的建议（如倾听、共情、正常化等回应方式），轻声提示而非教学 |
| **回应的多重价值** | ① 识别用户的身份特质与心理状态（人格识别的输入）；② 用户理想化存在方式的投射（他鼓励小猫做自己，可能正是他希望自己被允许做自己） |
| **明信片（影响力的证据）** | 小猫分享旅途见闻与生活状态，**联动此前用户给过的回应**——它因为用户的话做出了不同的选择，并分享尝试后的感受。**明信片回应的方向必须与用户当时的回应一致**（用户说"做自己"，明信片就是"做自己"的成功体验；详见 §5 示例） |
| **联动对应规则** | 需求卡事件（求助类）数量远多于明信片联动事件（回响类），实际执行中**随机对应即可，不要求一一对应**；但单次联动内部，明信片必须真实呼应用户给过的回应（红线：联动必须真实） |
| **探索钩子** | 小猫带用户发现多元世界：可能是远方的竹筏漂流，也可能是附近一个新垃圾堆、家里一个从未关注的角落——重新唤起对世界的好奇 |

## 4. 人格体系与预制内容库（控 AI 风险的前置工程）

> 设计原则：**不把内容生成交给 AI 自由发挥**。AI 的角色是"识别与匹配"，内容的主体是预制库。

### 4.1 人格识别方式（V2.1 修订）

- **不设独立 onboarding 环节**：用户选择小猫并起名字后，直接开始收到小猫的求助卡
- 通过识人期（1–2 天）相对密集的统一需求卡回应，**尽可能快地识别用户的人格倾向、潜在需求与问题**
- 识别结果驱动：小猫的性格倾向、需求卡选题、事件匹配、文案语气

### 4.2 内容库结构（V2.1 修订）

**事件不分型，分型的是需求与反馈。** 小猫的出行/旅行事件是通用的（所有用户的小猫都可能遇到）；人格差异体现在**事件发生后小猫提出的需求（需求卡）和给出的反馈**上。

| 内容库 | 结构 | 建议规模（待收敛会拍板） |
|--------|------|-------------------------|
| **出行/旅行事件库** | **不分型**，全用户通用。含事件结构、基础文案框架、配图；覆盖家与附近 / 城市探索 / 远方旅行 / 勇气与挑战四类场景 | 规模较 V2 大幅收敛，建议 100–150 个通用事件 |
| **需求卡库** | **按 I / E / N / S / T / F / J / P 八个字母维度划分**（16 型人格中每个特质由 4 个字母组成，如 INTJ = I+N+T+J），再结合最终的特质认定分配需求卡。**每型分配到的需求卡总数必须为 4 的倍数**（每字母维度等量贡献） | 建议每字母维度建 16 张母库（8 维共 128 张）；每型按 4 个字母各取 8 张 = **32 张/型**（4 的倍数）；含识人期统一卡 |
| **tips 库** | 20–30 个常见"回应困境"主题 | 由心理学/咨询专业内容撰写，人工审核 |

### 4.3 特质混合规则（V2.1 修订）

- 通过交互分析自然得出：有的用户是 **1 种特质**，有的用户是 **2 种特质**，**不超过 2 种**（不强制每人都是 2 种）
- 小猫的需求卡与反馈库随特质组合合并，**按特质占比按比例出现**

### 4.4 AI 限权原则（红线级）

- AI 只做三件事：**识别用户回应 → 匹配人格特质 → 关联预制事件与需求卡/文案框架**
- AI **不做**面向用户的开放式自由生成；模板内填空也必须有安全过滤
- 语音回应：后台语音转文字后做内容理解，**不做情绪识别**
- 理由：开放式生成存在质量失控、情感伤害、合规与法律风险（参照 AI 陪伴行业翻车与监管案例）
- 基础文案框架未来可结合用户互动微调，但始终在预制结构内、过审核管线

## 5. 感性描述（V2.1 版）

> 想象你养了一只属于自己的小猫。它是自由的，每天出门过自己的生活——但它信任你。
>
> 有一天它回家，留下一张小卡片：「今天是我第一次去隔壁小区，我有点担心，那里的小猫会不会不喜欢我？」
>
> 你想了想，用语音回了它一句：「先做你自己就好啦，喜欢你的小猫自然会被你吸引过来的。」
>
> 几天后，它寄回一张明信片：「我又去了隔壁小区。我没有凑过去讨好它们，就趴在墙头晒了一下午太阳。后来，一只三花猫主动走过来，挨着我趴下了。你说得对——做自己，真的会吸引喜欢你的朋友。」
>
> 那一瞬间你会愣一下：**你说出口的话，真的有力量。**它听见了，记住了，替你活出来了。
>
> 而你渐渐发现：那个会温柔安慰小猫、会告诉小猫"做自己就好"、会提醒小猫"累了就休息"的人，其实就是你自己。你一直在等的那些话，原来你自己就会说。

## 6. 产品本质

1. **养育即疗愈**：用户在满足小猫需求、回应小猫求助的过程中，练习"如何温柔地回应一个需求"——这份能力最终会反射回用户自身
2. **回应即投射**：用户给小猫的每一句回应，都是他理想化自我与潜在需求的显影——产品由此同时获得"懂用户"的窗口
3. **影响力确认**：明信片让用户看见"自己的话改变了一个生命"，确认自我效能感——被需要、有力量
4. **探索即好奇**：小猫带用户重新发现世界的多元（远方与身边），把"活着的质感"带回来

**为什么想做**：把"重新养育自己"从抽象的心理学概念，变成每天 3 分钟的、有生命感的具体实践。

## 7. 承接的心理学理念

| 理念 | 应用 |
|------|------|
| **Reparenting（重新养育自己）** | 核心机制。用户**亲自扮演养育者**，在养育小猫的过程中练习温柔回应需求——练习对象是小猫，内化对象是自己 |
| **温尼科特「足够好的母亲」** | 用户本人成为那个"足够好"的照顾者：不需要完美回应，只需持续真实在场。小猫绝不因用户的"不完美回应"而受伤或惩罚用户 |
| **叙事疗法「外化」** | 小猫是投射的安全载体：用户不敢对自己说的温柔，可以先对小猫说；不敢给自己的允许，可以先给小猫 |

---

## 8. 目标用户

有自我觉察意愿、但日常缺少稳定情感支持的年轻女性：对心理学/自我关怀内容有天然兴趣，对正式心理咨询尚未准备好或负担不起，需要低门槛、高情感回报、可融入碎片时间的陪伴方式。

---

## 9. 希望为用户带来的结果

| 时间维度 | 期望结果 |
|---------|---------|
| 短期 | 每天 3 分钟，体验"被需要"和"我的话有力量"；在回应小猫中获得情绪松弛 |
| 中期 | 在持续的"需求—回应—影响"循环中，看见自己回应模式的变化轨迹；通过明信片册沉淀"我给予过的温柔" |
| 长期 | 把对待小猫的方式内化为对待自己的方式——累了允许休息、害怕时鼓励自己、不完美时也值得被温柔以待；建立更稳定的自我认同 |

## 10. 已定规则与待讨论事项（V2.1 更新）

### 10.1 本次已敲定（罗比 2026-09-09 决策）

| 事项 | 结论 |
|------|------|
| 识人期时长 | **1–2 天**，相对密集的统一需求卡快速识别（原 7 天方案废弃） |
| 语音回应边界 | **只做内容理解**（后台语音转文字再识别），不做情绪识别 |
| 事件库分型 | **事件不分型**（全用户通用）；分型的是事件出来后小猫的需求和反馈（需求卡） |
| 需求卡划分 | 按 **I/E/N/S/T/F/J/P 八字母维度**划分，结合特质认定分配；每型总数为 **4 的倍数** |
| 特质混合 | 交互分析得出 **1 或 2 种特质**（不超过 2，不强制 2 种） |
| 商业化 | 原则确认：**记忆与回应质量永不进付费墙**；具体商业化规划暂不讨论，未来再说 |

### 10.2 后续单独设定规则（不进收敛会打包，单独成文）

- **人格识别准确性规则**：交互式认定的准确率如何验证、误配如何处理（"这只猫不像我的猫"）
- **需求卡供给节奏规则**：识人期 / 留存期 / 成熟期的卡片频率具体参数
- **情感安全规则**：用户在回应中暴露危机信号（自伤/抑郁）时的识别与转介——回应里藏着用户自己，红线 R3 适用且更重要

### 10.3 仍开放

- 载体形态（小程序 / App / H5）
- R9 透明粒度：是否向用户展示特质标签
- 内容库具体规模数字（建议值见 §4.2，待拍板）
