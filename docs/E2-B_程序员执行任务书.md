## 1. 本轮目标与边界

交付“离开与返回、单封未读新信及本机日历”。用户不需要按暂停／恢复按钮；关闭后经过时间，再打开可以读到留下的一封信，小猫处于当前应有的在家／旅行状态。读完不回也可等到下一次正常来信，不产生待补作业。

当前是 React／Vite＋IndexedDB 的 GitHub Pages 体验。正式入口保持 `https://zyrobbie.github.io/travel-cat-planner/app/`，数据库保持 `cat-letters-pages-v1` 与 `participants`，保留原参与者 hash 链接。E2-A 应用基线为 `ce2c31f0b3d47ae04137beacf6de76b0752b901c`；当前 HEAD 为后续文档提交 `d60500a765b11c3a4c9f59042f5baa0d05fbfdba`。

本轮新增按本机时间结算的实际能力，不能仅改控制台文案。网页关闭期间没有进程运行；重新打开时才计算并写入经过的节点。分别记录计划时间和实际写入时间，不伪造后台已投递。真实 Push、云账户、跨设备、语音、服务器 REALTIME、E5 自动语义匹配和 E3 正式图像不进入本轮。“留给自己的话”继续取消，不引入 PAUSED 或 HELD 产品状态。

## 2. 唯一产品规则

1. 需求卡与明信片共用一个未读新信位置；已有未读占位，不能覆盖、自动归档或偷偷标成已读。正常新版本从零／一封未读开始时，始终最多一封。不是每次打开必有新信，也不是每次离开额外送一封。
2. 没有未读时，独立日历中第一个到期且合法的来信节点可寄一封；后续因占位挡住的节点记为跳过，不加入待读后补发的队列。未到时间保持无新信。
3. 多日返回从上次进度按计划时间顺序结算旅行开始、来信、旅行结束等节点，旅行处理到当前时刻。第一封已经生成的信保留，不因后续旅行结束而撤回。不能先只计算当前旅行再挑最新信，也不能把离开期间每个节点都塞进来信盒。
4. 打开未读详情成功记录已读即释放位置。无需回应；跳过也是允许的行为。读完只为未来日历腾出位置，不立即重放刚才跳过的节点。回应确认仍只有“送出去啦。”，回应、阅读、未读上限不改变旅行资格、场景或日期。
5. 已寄信、收到日期、正文快照、阅读状态照常保留，旧旅行已结束也可看未读信。未寄且被跳过／取消的节点不形成用户欠账；用户主动管理、更正和删除资料的能力保持原义。
6. 实际投递仍检查当前有效的本体验来源、内容、旅行节点、安全状态和未读位置。自动日期结算不等于自动匹配：有当前有效、与该旅行场景相符的人工审核结果才寄 linked，否则用合法的同场景 ordinary。不得以过去的计划时刻绕过已经发生的来源删改；无可用内容则跳过并记录原因，不编正文。
7. 首读／回看、更正删除、版本冲突、安全输入检查继续遵循 E2-A。没有“恢复后才能回复”的限制，返回即可阅读和管理；刷新或前后台切换不能清空正在输入的草稿或把它自动发送。重新打开时若已有未读新信，优先呈现首页的新信入口，原草稿保留、打开原卡可恢复；正在编辑时新信到达，显示轻量入口，不自动切页、清空草稿或标记新信已读。

## 3. 本机日历与演示推进

- 计划持久化，包含初始化基点、计划版本、稳定节点 ID、排序依据、已结算位置与每节点结果。只有成功提交事务才推进位置；重入、刷新、两个标签、请求重试不会重复投递。无到期变化时避免持续空写和广播自激循环。
- 首次打开／刷新／选回原体验／返回前台时执行结算；页面可见期间也处理到期节点。不要依赖 `beforeunload` 成功执行，不要求浏览器在后台保活。页面异常或存储写失败必须可重试，不能显示空白新猫冒充原数据。
- 日历使用独立于响应次数的固定计划。默认沿用主方案 7.1 的 14 日内容顺序：D1 礼物、D3 陪伴、D5 抓虫、D6 出发、D7 萤火虫信、D8 回家、D9 泡泡、D10 阿橘、D11 鱼干、D12 出发、D13 灯塔信、D14 回家；莱茵河用于保留的人工场景。以日历初始化时刻为基点，D1 为 +24 小时，后续 Dn 为 +n×24 小时，记录为工程默认而非用户作息承诺。不在首次命名或升级瞬间自动补一轮旧事件。
- 旧版已寄过的内容不重复；某节点对应内容已使用时记录跳过，不能改成自动找未读／最近回应来改变场景。有限日历／内容耗尽后保留生活状态、来信盒和手动演示，不循环重寄，也不宣称长期内容已覆盖。
- 提供清楚标注的“演示快进到下一节点”等最短验收方式，快进使用相同结算规则；至少能跨越多个节点和一次旅行结束。不要改系统时钟，不把模拟时间记成真实后台运行。实际本机时间与演示时间不能互相倒退、重放或同时争抢同一旅行。
- 保留现有人工推进用于体验三组故事。人工投递也必须走同一未读名额、内容唯一性、旅行和来源检查；手动结束的旧旅行不能被稍后到期的旧结束节点误作用于新旅行。人工操作如何与日历节点协作应写入开发记录，不新增可绕过规则的“强制寄出”。
- 时钟倒退不倒退已处理位置；大幅前跳只能结算有限已知节点。模拟时钟与本机时间的偏移、刷新恢复方式明确可测试，不能因重复 focus 事件推进多个“天”。

## 4. 旧数据升级

保留现有猫、全部信件与 ID、正文快照、收到／阅读／跳过时间、所有回应版本与删除标记、sourceRefs、review、原 trip.id、tripCount、历史事件与请求幂等记录。迁移原子完成，未知／损坏版本中止并保留原数据。不能换库、清库、新建猫或修改旧已读状态来满足新规则。

- 旧版多封未读是兼容遗留，全部保留并可从来信盒阅读；未读清空前不再新增。不能只隐藏旧信，让内部仍继续积压。
- 新日历在首次升级时初始化，不根据旧建档日期倒推历史发信。已经开始的旅行继续使用原 ID，给缺少时间字段的旧旅行增加明确的剩余计划；已有寄信不增加第二封，已有人工审核关系不丢失。
- 程序员开工方案已由统筹确认：旧旅行以升级基点 +24 小时增加一次寄信机会、+48 小时回家；已有寄信则跳过该机会。场景优先保留该旅已有人工选择，其次已寄信场景，否则采用明确的工程默认莱茵河。后续完整 14 日日历从这段剩余安排的结束点起算，避免冲突；这些是新增安排，不冒称原来已有时间字段。手动新旅行同样绑定原子创建的确切 tripId，并计划 +1 日寄信、+2 日结束；它与既有日历出发节点冲突时必须记录明确处理结果，不替换正在进行的旅行或临时挪动固定日历。
- 保留从 E0＋E1 直接升级及从 E2-A 升级的路径。冻结旧程序生成真实合成数据作为夹具，至少包含多封未读、已读未回、已回、已删／已改来源、未寄 linked 和进行中的旅行。测试专用构造／时钟注入不得进入公开可绕过规则的产品入口。

## 5. 修正普通与关联寄信入口

上轮已确认的交互问题一并收口：上方“寄出旅行明信片”实际只寄 ordinary，且能使已经选好的 linked 过期。

- 普通投递入口应明确标成普通故事，并说明其用途；保留零回应也可独立旅行和寄 ordinary。
- 已有人工选择的待寄结果时，明确展示所选类型与实际标题，以“寄出已选旅行信”作为对应操作。误点普通入口不能悄悄取代已选关联信；需要改选时走明确选择流程。
- 同时保护状态层，不能只改按钮文案；旧标签或重复请求不能绕过已选结果、未读名额和每趟一封的限制。
- 不加关键词匹配、样例全文匹配或默认勾选来伪装自动理解。E5 保持后续阶段。

## 6. 必须交付的验收证据

| 场景 | 正确结果 |
|---|---|
| 短暂离开，未到任何节点 | 没有新信，重复打开不产信 |
| 空位离开，跨多张卡和旅行 | 第一封合法来信保留，最终旅行状态正确，其余节点跳过不排队 |
| 离开前已有未读 | 返回仍是原信和原阅读状态，不追加；旅行独立继续 |
| 已读未回复／只跳过 | 下一个未来节点仍能来信；读完瞬间不补发遗漏节点 |
| 旅行信先生成，之后旅行结束 | 当前回家，原未读旅行信仍可首读、收好、回看来源 |
| 旧 E2-A 多未读及进行中旅行升级 | 所有旧值保留，原旅行 ID 延续，多未读处理符合兼容规则 |
| E0＋E1 直接升级及失败重试 | 升级链完整，无重复、清库、回应或删除状态复活 |
| 双标签同时返回、读取与到期投递并发 | 真实 IndexedDB 事务下最多一封新增未读，一节点一次，原更新不丢 |
| 一次跨多日与分段结算等价 | 没有额外用户动作时，可见信件、旅行状态及节点结果一致；实际落库时间等运行观测字段除外 |
| 先结算再标已读 | 打开未读信前先处理此前到期节点，不能先释放位置再塞入本应跳过的旧节点 |
| 待寄来源删改及安全覆盖 | 不复活失效来源，不借历史时间绕过当前检查；已寄历史处理保持 E2-A |
| 普通／关联入口及旧标签操作 | 三篇 linked 可人工寄出；已选 linked 不被普通按钮静默替换，所有入口遵循同一名额 |
| 时钟倒退、前跳、重复事件、写入失败 | 不重放、不重复消费，失败原子回滚，重试返回一致结果 |
| 页面与发布包 | 390px 与桌面真实操作及 PNG 可读；无占位暂停／Push 按钮，无测试后门或私有存档打包 |

使用项目现有测试工具；受影响的原 Pages／E2-A 用例应调整为先读信或明确旧版夹具，不能移除既有来源／迁移保障来让测试通过。至少完成 pages:build、typecheck、content:check、原 Pages 与 E2-A 相关回归、新 E2-B 日历／升级／并发测试。涉及共享 Node 类型或页面时跑相应构建；纯本机能力不夸称服务端、实际手机或真实 Push 已通过。

自动时钟测试与真实浏览器重新打开验证分开记录。提供一条不超过五步的可用体验路径；不得要求用户等完整 14 天才能确认规则。生成合成样本与截图留在忽略目录或 /tmp，不读写用户私有浏览器存档。
